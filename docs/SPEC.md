# 3D-MOVIE 仕様書(ドラフト v0.1)

プロンプトから 3D モデルアセットを生成し、それを動かして動画にするまでを一気通貫で行うプロダクト群の仕様たたき台。
2 つのアプリと、その間をつなぐ共通アセットライブラリで構成する。

| 名称 | 役割 | 一言で |
|---|---|---|
| **Forge**(アセット生成) | テキスト/画像 → 3D モデル(メッシュ+テクスチャ+任意でリグ) | 「作る」 |
| **Studio**(アニメーション/動画) | モデルを配置・動かし・撮影して MP4 に書き出す | 「動かして撮る」 |
| **Library**(共通基盤) | 生成物の保存・バージョン管理・メタデータ・ジョブ管理 | 「つなぐ」 |

---

## 1. ゴールと非ゴール

### ゴール
- 3D の専門知識がないユーザーが、文章だけで「キャラクター/小物/背景」を作り、短い動画(〜60 秒)を完成させられる。
- 生成物は標準フォーマット(glTF/GLB)で持ち出せ、Blender・Unity・Unreal 等でも使える。
- 生成 → 修正 → 再生成のループが速い(1 回あたり数十秒〜数分)。

### 非ゴール(v1 では扱わない)
- フォトリアルな長尺映像(VFX レベル)の制作。
- 本格的なモデリング/スカルプト機能(頂点編集など)。Blender の代替は目指さない。
- マルチユーザーのリアルタイム共同編集。

---

## 2. ターゲットユーザーとユースケース

| ユーザー像 | 代表的なユースケース |
|---|---|
| 個人クリエイター / VTuber 周辺 | オリジナルキャラを作ってショート動画・MV を作る |
| インディーゲーム開発者 | 敵キャラ・小物を量産し、PV 用の動画も作る |
| マーケ / 広告制作者 | 商品モチーフの 3D を作り、SNS 向け 10〜15 秒動画を量産 |
| 教育・プレゼン用途 | 概念モデル(細胞、機械など)を作り、説明アニメにする |

代表シナリオ:
1. Forge で「赤い鎧を着た小さなドラゴンの騎士、ローポリ、ゲーム風」と入力 → 4 候補生成 → 1 つ選択 → テクスチャ再生成 → 自動リグ → ライブラリに保存。
2. Studio で新規シーン → ライブラリからドラゴン騎士と背景「中世の城の中庭」を配置 → モーションを「剣を抜いて構える、その後ジャンプ」と指示 → カメラを「ローアングルからゆっくり寄る」と指示 → プレビュー → 1080p/30fps で書き出し。

## 3. 全体アーキテクチャ

```
┌────────────────┐      ┌────────────────┐
│  Forge (Web)   │      │  Studio (Web)  │
│  生成 UI       │      │  タイムライン/3D ビュー │
└───────┬────────┘      └───────┬────────┘
        │  REST / WebSocket(ジョブ進捗)  │
        ▼                                ▼
┌─────────────────────────────────────────────┐
│               API Gateway / BFF             │
│   認証・アセット CRUD・ジョブ投入・課金/クォータ   │
└───────┬──────────────────────┬──────────────┘
        │                      │
        ▼                      ▼
┌────────────────┐    ┌──────────────────────┐
│ Asset Library  │    │   Job Queue (Redis等) │
│ DB + Object    │    │   ワーカー群          │
│ Storage        │    │  ├ gen-3d (生成)       │
│ (GLB/テクスチャ/ │    │  ├ rig    (リギング)   │
│  サムネ/メタ)    │    │  ├ motion (モーション生成)│
└────────────────┘    │  └ render (動画レンダリング)│
                      └──────────────────────┘
```

設計方針:
- **2 アプリは独立してデプロイ可能**だが、同一モノレポで共通パッケージ(アセット型定義・API クライアント・3D ビューア)を共有する。
- **重い処理はすべて非同期ジョブ**。UI は進捗をリアルタイム表示し、完了時に通知。
- **生成エンジンはプラガブル**。外部 API(後述)と自前 GPU 推論を同じインターフェースで差し替えられるようにする。

## 4. Forge(アセット生成アプリ)

### 4.1 機能要件

| ID | 機能 | 優先度 |
|---|---|---|
| F-1 | テキストプロンプトから 3D モデルを生成(複数候補、デフォルト 4) | MVP |
| F-2 | 参照画像(1 枚〜複数)からの 3D 化(image-to-3D) | MVP |
| F-3 | スタイルプリセット(ローポリ / アニメ調 / リアル / ボクセル / クレイ)とネガティブ指定 | MVP |
| F-4 | 生成結果のブラウザ内 3D プレビュー(回転・ズーム・ワイヤーフレーム・UV 表示) | MVP |
| F-5 | 「このメッシュのままテクスチャだけ再生成」(リテクスチャ) | MVP |
| F-6 | ポリゴン数ターゲット指定とリメッシュ/デシメーション | v1 |
| F-7 | 自動リギング(人型/四足/汎用)とウェイト確認用ポーズプレビュー | v1 |
| F-8 | 部分修正(「翼を大きく」等のプロンプト差分再生成) | v2 |
| F-9 | エクスポート: GLB / glTF / FBX / OBJ / USDZ、テクスチャ解像度選択 | MVP(GLB)/ v1(他) |
| F-10 | アセットのバージョン履歴・派生ツリー(どのプロンプトから分岐したか) | v1 |
| F-11 | タグ・検索・コレクション管理 | v1 |
| F-12 | プロンプト補助(LLM によるプロンプト拡張・3D 向け言い換え) | v1 |

### 4.2 画面構成

1. **ホーム / ライブラリ**: 生成済みアセット一覧(サムネ付きグリッド)、検索、コレクション。
2. **生成画面**: 左にプロンプト・スタイル・参照画像・詳細設定、中央に候補 4 枚のサムネ、右に選択中の 3D プレビュー。
3. **アセット詳細**: 3D ビューア、メタデータ(ポリゴン数・テクスチャ・リグ有無)、派生履歴、アクション(リテクスチャ・リグ・エクスポート・Studio で開く)。
4. **ジョブ一覧**: 実行中/完了/失敗ジョブとログ。

### 4.3 生成パイプライン(ステージ)

```
prompt/画像 ─▶ [1] プロンプト正規化(LLM)
            ─▶ [2] 候補画像生成(マルチビュー画像、任意)
            ─▶ [3] 3D 生成(メッシュ + 初期テクスチャ)
            ─▶ [4] 後処理(法線修正、穴埋め、スケール正規化、原点合わせ)
            ─▶ [5] テクスチャ高解像度化 / PBR 分離(Albedo, Normal, Roughness, Metallic)
            ─▶ [6] 任意: リメッシュ / リギング
            ─▶ [7] GLB 書き出し + サムネ生成 + メタデータ登録
```

各ステージは独立ジョブとし、途中からやり直せる(例: [5] だけ再実行 = リテクスチャ)。

### 4.4 生成エンジン(候補)

| 方式 | 候補 | 長所 | 短所 |
|---|---|---|---|
| 外部 API | Meshy, Tripo3D, Rodin(Hyper3D), Stability 3D 系 | 立ち上げが速い、品質が安定、リグ/アニメ付きのものもある | 従量課金、ライセンス条件、ベンダーロック |
| 自前推論(OSS) | Hunyuan3D 2.x, TRELLIS, TripoSG/TripoSR, InstantMesh | コスト制御、カスタマイズ性、データが外に出ない | GPU 運用コスト、品質チューニングが必要 |

**推奨**: MVP は外部 API 1〜2 社をアダプタ経由で利用し、`GenerationProvider` インターフェース(`generate(prompt, options) -> job`, `retexture`, `rig`)で抽象化。v1 以降で OSS モデルの自前ワーカーを同じインターフェースで追加し、コストや品質で切り替える。

## 5. Studio(アニメーション / 動画アプリ)

### 5.1 機能要件

| ID | 機能 | 優先度 |
|---|---|---|
| S-1 | シーン作成、ライブラリからアセットをドラッグ配置(位置・回転・スケール) | MVP |
| S-2 | 3D ビューポート(ギズモ操作、グリッド、ライト表示) | MVP |
| S-3 | **モーション指示**: 自然言語 → モーションクリップ(「歩く」「手を振る」「ジャンプして着地」) | MVP |
| S-4 | モーションライブラリ(既製クリップの検索・プレビュー・適用、リターゲット) | MVP |
| S-5 | タイムライン(トラック: オブジェクトごとのモーション/トランスフォーム/カメラ/音声) | MVP |
| S-6 | カメラ: 手動キーフレーム + 自然言語プリセット(「ゆっくり寄る」「周囲を一周」「ローアングル」) | MVP |
| S-7 | ライティングプリセット(スタジオ / 屋外昼 / 夕暮れ / ネオン)と HDRI | MVP |
| S-8 | 背景: 単色 / HDRI / Forge 生成の環境モデル / 生成パノラマ画像 | v1 |
| S-9 | キーフレーム編集(トランスフォーム、イージングカーブ) | v1 |
| S-10 | モーションのブレンド・トリム・ループ・速度変更 | v1 |
| S-11 | 複数キャラの掛け合い(「A が B に近づいて握手」) | v2 |
| S-12 | リップシンク / 音声からの表情アニメ | v2 |
| S-13 | **レンダリング**: 解像度(720p/1080p/4K)、fps(24/30/60)、形式(MP4 H.264 / WebM / PNG 連番 / 透過 WebM) | MVP |
| S-14 | ドラフト(ブラウザ高速)と高品質(サーバー)の 2 段レンダリング | v1 |
| S-15 | テンプレート(ターンテーブル、商品紹介、キャラ紹介)からのワンクリック動画 | v1 |
| S-16 | BGM / 効果音トラック、字幕/テロップ | v1 |

### 5.2 画面構成

```
┌──────────────────────────────────────────────────────────┐
│ ツールバー(保存 / Undo / 再生 / レンダリング)                  │
├──────────┬────────────────────────────────┬──────────────┤
│ アセット   │                                │ プロパティ     │
│ パネル    │        3D ビューポート            │ (選択物の     │
│ (ライブラリ│                                │  Transform/   │
│  モーション│                                │  マテリアル/   │
│  カメラ)  │                                │  モーション設定)│
├──────────┴────────────────────────────────┴──────────────┤
│ タイムライン(トラック / クリップ / キーフレーム / 再生ヘッド)        │
├──────────────────────────────────────────────────────────┤
│ プロンプトバー:「ドラゴンが右に歩いて止まり、カメラは正面から寄る」   │
└──────────────────────────────────────────────────────────┘
```

プロンプトバーは **シーン編集の操作そのもの** を自然言語で受け付ける(モーション追加・カメラ設定・ライト変更)。LLM がシーン JSON への差分操作に変換し、Undo 可能な編集として適用する。

### 5.3 モーション生成の仕組み

1. **ライブラリ検索ベース(MVP)**: 自然言語 → LLM がライブラリ内クリップ(歩く・走る・ジャンプ等、数百種)を選択・連結・パラメータ化 → ボーン名マッピングでリターゲット。
2. **生成モデルベース(v1〜)**: テキスト→モーション生成モデル(MDM / MotionGPT 系、SMPL/HumanML3D ベース)で未知の動きを生成し、同じリターゲット経路で適用。
3. **非人型・小物**: トランスフォームアニメ(バウンド、回転、浮遊、揺れ)をプロシージャルに生成。人型以外のリグは「汎用ボーンチェーン + 簡易 IK」で対応。

### 5.4 レンダリングパイプライン

| モード | 実装 | 用途 |
|---|---|---|
| ドラフト | ブラウザ内 Three.js(WebGL/WebGPU)でフレームを連続キャプチャ → WebCodecs / ffmpeg.wasm で MP4 化 | すぐ確認したい、SNS 用に十分な画質 |
| 高品質 | サーバー側: シーン JSON → Blender ヘッドレス(EEVEE Next / Cycles)または Three.js ヘッドレス(GPU インスタンス)→ ffmpeg | 最終出力、4K、被写界深度・モーションブラー |

シーンは **1 つのシーン定義 JSON** を正とし、ブラウザとサーバーの両レンダラが同じ JSON を解釈する。見た目差は許容範囲を定義し、プリセット単位で検証する。

## 6. 共通基盤(Library)

### 6.1 アセットデータモデル(概略)

```jsonc
{
  "id": "ast_01H...",
  "type": "model | motion | environment | audio",
  "name": "ドラゴン騎士",
  "version": 3,
  "parent_id": "ast_01G...",          // 派生元
  "prompt": { "text": "...", "negative": "...", "style": "lowpoly", "seed": 1234 },
  "provider": { "name": "meshy", "model": "v5", "job_id": "..." },
  "files": {
    "glb": "s3://.../model.glb",
    "textures": { "albedo": "...", "normal": "...", "orm": "..." },
    "thumbnail": "...",
    "source_images": ["..."]
  },
  "stats": { "triangles": 12000, "materials": 1, "texture_size": 2048, "bounds": [x, y, z] },
  "rig": { "type": "humanoid | quadruped | generic | none", "bone_map": "mixamo-compatible" },
  "tags": ["character", "fantasy"],
  "license": "owner | cc0 | provider-terms",
  "created_at": "...", "owner_id": "..."
}
```

### 6.2 ファイル形式
- **正: glTF 2.0 / GLB**(PBR、スキン、アニメーションをすべて格納できるため)。
- モーションは GLB 内アニメーション、または独立した `.glb`(ボーンのみ)で保存し、ボーン名規約(Mixamo / VRM 互換)を定める。
- シーンは独自 JSON(バージョン付き)。将来 USD へのエクスポートを検討。

### 6.3 ジョブ管理
- ジョブ種別: `generate_3d`, `retexture`, `remesh`, `rig`, `generate_motion`, `render_video`。
- 状態: `queued → running → succeeded | failed | canceled`、進捗率とステージ名を持つ。
- WebSocket(または SSE)で UI に進捗配信。失敗時は原因分類(プロバイダエラー / NSFW 判定 / タイムアウト)を返す。

### 6.4 認証・課金・安全性
- アカウント(メール / OAuth)。生成クレジット制(生成・レンダリングでクレジット消費)。
- プロンプトと出力の安全性フィルタ(実在人物・商標・不適切コンテンツ)。
- 生成物の利用規約を明示(プロバイダのライセンスを継承)。

## 9. ロードマップ

### MVP(〜3 か月目安)
- Forge: テキスト/画像 → GLB(外部 API 1 社)、4 候補、プレビュー、リテクスチャ、GLB エクスポート、ライブラリ保存。

### v2

## 10. 未決事項(要相談)

1. **提供形態**: Web アプリ中心か、デスクトップ(Electron / Tauri)も視野に入れるか。GPU をユーザー側で使うなら後者が有利。
2. **生成エンジン方針**: 立ち上げは外部 API で良いか、最初から自前 GPU 推論にこだわるか(コスト・データ保護・品質の優先度)。
3. **品質ターゲット**: ゲーム向けローポリ寄りか、映像向けハイポリ寄りか。モーション・レンダリングの設計が変わる。
4. **主要ターゲット**: 「キャラクター中心」か「商品・小物中心」か。前者ならリグ/モーションが MVP の中核、後者ならターンテーブル・ライティングが中核。
5. **2 アプリの分け方**: 別 URL・別プロダクトとして出すか、1 つのアプリ内の 2 モード(「作る」「動かす」)にするか。
6. **収益モデル**: クレジット制 / サブスク / 無料+エクスポート課金。
7. **対応言語**: 日本語 UI のみか、英語も同時か。
